# Постижения (Tracker)

Уеб приложение за хакатон. Ученик пише името си и вижда резултатите си от националните олимпиади, взети от публичните протоколи на МОН.

Търсенето разбира имена, написани:
- на латиница: „Aleksandar Bangachev“ → Александър Атанасов Бангачев;
- с правописна грешка: „Кирил Зулямки“ → Кирил Иванов Зулямски;
- с умалително име: „Митко Митанкин“ → Димитър Петров Митанкин (речник с ~100 умалителни);
- само с фамилия: „Керацов“;
- в изречение: „казвам се Виктория Димова“ → Виктория Красимирова Димова *(ИИ)*.

## Как работи

### Търсене

```
текст ─┬─ NicknameDictionary ─────────────┐
       └─ QueryInterpreter (Ollama) ─────┴→ NameNormalizer → NameMatcher (Jaro-Winkler) → MySQL
```

- **`NicknameDictionary`** заменя често срещаните умалителни („Митко“ → Димитър), които малките модели не знаят.
- **`QueryInterpreter`** изпраща текста на локален модел (`qwen2.5:7b` в Ollama), който извлича името от изречението. Ако Ollama не работи или се бави повече от 3 секунди, стъпката се прескача и търсенето продължава без нея.
- **`NameNormalizer`** превръща текста в малки букви, маха пунктуацията и транслитерира латиница → кирилица.
- **`NameMatcher`** оценява сходството на всяка дума с имената в базата и предлага „Имахте предвид…?“. Съвпадение има само когато всяка дума е близка, така че общо собствено име и общо окончание „-ова“ не стигат.

Надписът 🤖 се показва само когато моделът е намерил ученик, когото речникът и алгоритъмът сами не намират.

### Данни от МОН (`Tracker.Importer`)

```
PDF протокол ─► TableReader (позиции на думите) ─► ColumnMapper (ИИ, веднъж на таблица)
            ─► RowBuilder ─► RowValidator ─► Deduplicator ─► import-review.csv ─► import ─► MySQL
```

- **`TableReader`** сглобява таблиците от позициите на думите в PDF-а: колоните са на едно и също място на всяка страница, включително продълженията без заглавен ред. Пренесените имена и числа се присъединяват към реда си.
- **`ColumnMapper`** пита локалния модел коя колона е име, клас, общ брой точки и място („Общ бр. точки“, „Общо“, „Резултат“, „Приз“…). Отговорът се проверява: колоната с точки трябва да съдържа числа, подредени като класиране.
- **`RowBuilder`** чете стойностите директно от PDF-а (без закръгляне), а **`RowValidator`** отхвърля редове без истинско име или без точки.

Импортирани протоколи (национални кръгове 2025/2026): математика, информатика, физика, химия, биология, български език — **609 резултата за 537 ученици**. Загуба при разчитането: 0–3% на протокол. Изключение е една таблица по биология (49 ученици), чийто заглавен ред моделът не разпознава. Списъкът е в `Tracker.Importer/protocols.json`.

Пазят се само име, клас, точки, място и линк към протокола (без училище и град). Всеки резултат в приложението сочи към оригиналния протокол. Свалените PDF-и и CSV-то за преглед не са в git.

Кодът е в `Tracker/Search/` и `Tracker.Importer/`, а дизайнът е в `docs/superpowers/specs/`.

## Бързо пускане (след като всичко е настроено)

```bash
powershell -ExecutionPolicy Bypass -File start.ps1
```

Скриптът пуска MariaDB (ако не работи), Ollama (ако е инсталиран), приложението и браузъра на http://localhost:5011. Ако нещо вече работи, само го отбелязва. С `-NoBrowser` не отваря браузъра. Приложението се спира с Ctrl+C, а MariaDB и Ollama продължават да работят на заден план.

## Пускане от нулата

Нужни са .NET 9 SDK, MySQL или MariaDB и [Ollama](https://ollama.com) (по желание за търсенето, задължително за импорта).

1. Connection string в `Tracker/appsettings.Development.json` (файлът не е в git):
   ```json
   { "ConnectionStrings": { "Tracker": "Server=localhost;Port=3306;Database=tracker;User=root;Password=...;CharSet=utf8mb4" } }
   ```
2. Таблиците:
   ```bash
   dotnet tool restore
   dotnet ef database update --project Tracker
   mariadb -uroot -p --default-character-set=utf8mb4 < db/schema.sql
   ```
3. Моделът (името е в `appsettings.json` → `Ollama:Model`):
   ```bash
   ollama pull qwen2.5:7b
   ```
   (~4.7 GB. На по-слаб компютър: `qwen2.5:3b` е по-малък, но понякога връща грешен ученик.)
4. Данните от МОН: `extract` сваля протоколите и пише `Tracker.Importer/import-review.csv` за преглед; `import` записва редовете със статус `ok`:
   ```bash
   dotnet run --project Tracker.Importer -- extract
   dotnet run --project Tracker.Importer -- import
   ```
5. Стартиране:
   ```bash
   dotnet run --project Tracker
   ```
   и отворете http://localhost:5011

Без Ollama: задайте `"Ollama": { "Enabled": false }`. Търсенето продължава да работи, без заявките в изречение.

## Тестове

```bash
dotnet test
```

`db/model-check.ps1` проверява търсенето с 22 заявки върху реални ученици (умалителни, грешки и латиница, само фамилия, изречения, несъществуващ ученик) през истинския `/api/search`. Последно измерване:

| | Верни | Грешен ученик с 🤖 | Средно време |
|---|---|---|---|
| без ИИ (речник + алгоритъм) | 17/22 | 0 | ~25 ms |
| **с qwen2.5:7b** | **21/22** | **0** | ~210 ms |

Без ИИ не минават заявките в изречение. С ИИ не минава „покажи ми Цвети Пенчева“: моделът отговаря „Цвета“ вместо „Цветелина“.
